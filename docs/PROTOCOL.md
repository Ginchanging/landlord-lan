# 局域网通信协议 v1

房主通过 `HttpServer.bind(InternetAddress.anyIPv4, 0)` 分配空闲 TCP 端口，只接受 `/play` 路径的 WebSocket 升级。通过 `_doudizhu._tcp` 广播 DNS-SD 服务，TXT 字段 `name` 为名称、`v` 为协议版本。手动连接使用相同端点。

客户端只接受私有、环回、链路本地或 IPv6 ULA 数字地址，不解析公共域名，也不连接公共互联网 IP。首版房主使用 IPv4，自动发现请求 IPv4。Socket 为本地 `ws://`，客户端直接连接，绕过 HTTP 代理。

## 加入与身份

```json
{"type":"join","protocol":1,"name":"牌友","token":null}
```

房主预留首座。新玩家获得新座位；重连时提交首次 `welcome` 中的 token 恢复原座位，不依据昵称识别。token 是安全随机生成的 32 字节字符串，仅发给该玩家，不进入公开牌局或日志。首帧限时 5 秒；昵称为 1～12 个字符；仅三个座位。

`welcome` 包含 `playerId`、`token`、`protocol`，随后发送 `state`。版本不匹配或座位无效时发送带 `fatal: true` 的 `error` 并关闭连接。

## 操作与状态

```json
{"type":"action","id":"随机前缀-递增序号","revision":12,"action":"play","data":{"cards":[0]}}
```

- `ready`：`{"ready":true}`，三人准备即自动发牌。
- `bid`：`{"score":0}`，0 表示不叫，其他合法分值为 1～3。
- `play`：`{"cards":[0,1]}`，牌 ID 为 0～53。
- `pass`：`{}`。
- 单帧只接受不超过 8192 字符的 JSON 文本；服务端验证轮次、牌型、所属手牌和版本。
- 每个玩家记忆最近 256 个成功操作 ID；重复成功操作只返回最新状态及 `ack`。版本过期或非法操作返回 `error` 和当前状态，不自动重放。
- `state` 是每个玩家单独构建的快照：版本、阶段、轮次、自己的 `hand`、公开玩家信息、地主、已公开底牌、出牌、倍数和结算。不包含他人手牌或牌堆顺序；叫分时隐藏底牌。
- 牌 ID 0～51 按点数 3～2、每点数依次梅花/方块/黑桃/红桃；52 小王、53 大王。

## 心跳与断线

服务端每秒发送 `ping`，客户端回 `pong`；8 秒没有消息视为连接失活。断线不自动重复出牌。

`suspend` 在进入后台时提前暂停，`leave` 表示主动退出。游戏中首次断线设不可延期的 60 秒截止时间，全部重连清除暂停，超时中止本局。非游戏阶段离线座位也保留 60 秒。房主离线超时关闭房间。

房主恢复前台时先检查当前时间，避免系统冻结定时器后继续已经超时的局。房主进程死亡不迁移牌局。

截止时间以 UTC 传递，另带 `remainingMs`。客户端以剩余时长建立本机截止时间，避免手机时钟或时区差异导致提前超时；最终是否中止由房主决定。
